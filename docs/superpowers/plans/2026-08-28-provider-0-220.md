# Provider 0.220 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modernize the S3 module for Yandex provider 0.220 without breaking existing module inputs.

**Architecture:** Keep bucket creation in `yandex_storage_bucket`, but manage deprecated inline grants and policies through dedicated provider resources. Extend existing variable objects and lifecycle blocks only for newly exposed provider capabilities.

**Tech Stack:** Terraform >= 1.3, Yandex provider 0.220, HashiCorp AWS provider for IAM policy-document generation.

**Spec:** `docs/superpowers/specs/2026-08-28-provider-0-220-design.md`

## Global Constraints

- Keep `acl`, `grant`, and `policy` caller inputs backward compatible.
- Do not add Terraform tests, per user request.
- Require Yandex provider `>= 0.220.0, < 0.221.0`.
- Do not change defaults or enable static-key blocking by default.

### Task 1: Move deprecated policy and grant management

**Files:**
- Modify: `main.tf:57-74`
- Modify: `policy.tf:1-110`

**Interfaces:** Existing `var.grant`, `var.policy`, `var.policy_console`, and `data.aws_iam_policy_document.this` produce one optional `yandex_storage_bucket_grant.this` and one optional `yandex_storage_bucket_policy.this`.

- [ ] **Step 1: Remove deprecated inline arguments**

Delete the bucket's `dynamic "grant"` block and direct `policy` assignment; keep `acl` on `yandex_storage_bucket.this`.

- [ ] **Step 2: Add a single grant resource**

```hcl
resource "yandex_storage_bucket_grant" "this" {
  count  = length(var.grant) > 0 ? 1 : 0
  bucket = yandex_storage_bucket.this.bucket

  dynamic "grant" {
    for_each = var.grant
    content {
      id          = grant.value.id
      type        = grant.value.type
      uri         = grant.value.uri
      permissions = grant.value.permissions
    }
  }
}
```

- [ ] **Step 3: Add a policy resource**

```hcl
resource "yandex_storage_bucket_policy" "this" {
  count  = var.policy.enabled || var.policy_console.enabled ? 1 : 0
  bucket = yandex_storage_bucket.this.bucket
  policy = data.aws_iam_policy_document.this[0].json
}
```

- [ ] **Step 4: Verify formatting**

Run: `terraform fmt -recursive && terraform fmt -check -recursive`

Expected: exit code 0 and no unrelated files change.

- [ ] **Step 5: Commit**

Run: `git add main.tf policy.tf && git commit -m "feat: use dedicated storage policy and grant resources"`

### Task 2: Expose security and lifecycle capabilities

**Files:**
- Modify: `variables.tf:473-675`
- Modify: `main.tf:130-170`

**Interfaces:** `var.disabled_statickey_auth` is nullable and defaults to `null`. Each `var.lifecycle_rule` may add `filter` and `newer_noncurrent_versions` without invalidating prior inputs.

- [ ] **Step 1: Extend the variable types**

Add optional `disabled_statickey_auth` (`bool`, default `null`). Add this optional lifecycle object:

```hcl
filter = optional(object({
  object_size_greater_than = optional(number)
  object_size_less_than    = optional(number)
  prefix                   = optional(string)
  tag = optional(object({ key = string, value = string }))
  and = optional(object({
    object_size_greater_than = optional(number)
    object_size_less_than    = optional(number)
    prefix                   = optional(string)
    tags                     = optional(map(string))
  }))
}))
```

Add optional `newer_noncurrent_versions` to both noncurrent-version objects and update descriptions to include `ICE` and `INTELLIGENT_TIERING`.

- [ ] **Step 2: Render the new provider arguments**

Pass `disabled_statickey_auth = var.disabled_statickey_auth` to the bucket. Add dynamic lifecycle `filter`, nested `tag`, nested `and`, and `newer_noncurrent_versions` mappings in the existing lifecycle blocks.
